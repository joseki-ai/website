The basics
What is Joseki?

Infrastructure for building and testing trading strategies: market data captured in colocation, a feature library, a market simulator configurable from the order book to daily bars, and managed machine learning, connected in one workflow.

Joseki is software. We do not manage money, give investment advice or trade on customers' behalf.

Who is it for?

Quant teams across horizons: market makers and HFT desks, intraday and systematic portfolio traders, and machine-learning teams building trading models.

What do I get from a run?

A ledger per market: every order, fill, fee and position, with realized and unrealized profit and loss, every fill linked to the market event that caused it, a comparison with the same run taking no action, and for sweeps a ranked table of every setting. All of it is inspectable in the browser.

Each run records the dataset versions, feature definition versions, configuration and build it used. Re-running the same inputs produces an identical result, byte for byte.

How do I get access, and what does it cost?

We are running a private pilot. Tell us what you trade and what you want to test, and we agree scope and terms with each team. During the pilot we run the jobs on our hardware, so there is nothing to install. Request access.

Trust and data
Is my strategy safe with you?

Customer workloads run on confidential GPUs inside a hardware-isolated enclave: CPU memory is encrypted by the processor, GPU memory sits in a protected region, and transfers between them are encrypted. Keys are released only after the enclave proves, by remote attestation, what it is running. Nobody outside the enclave can read the code or the data: not other tenants, not Joseki staff, not the root user of the host.

Each pilot also runs under a written agreement: customer code and data are used only to run the customer's tests, never for our own trading, and are deleted on request.

Which markets do you cover?

Equities, futures, options, FX and event contracts, added venue by venue and recorded from the day each venue is added. Tell us the venues you need and we will tell you when they are ready.

Do I need to download or store the data?

No. Strategies, feature computations, simulations and training jobs read the data where it is stored, and history is retained and versioned on the platform. The SDK provides programmatic access for analysis.

Under the hood
How close is the simulation to a real market?

Queue position, latency, fees, partial fills and market impact are models set per venue and per run, with conservative defaults. Every simulated fill is linked to the market event that caused it.

How is queue position modeled?

Where the venue publishes order-level data, an order takes its exact place in the queue. With price-level data, the queue position is estimated, back of the level by default, and advances only as trades consume the size ahead. The matching rule, FIFO or pro-rata, follows the venue.

Can I set my own latency?

Yes. Feed, order entry and order acknowledgement latencies are separate settings, fixed or sampled from measured distributions.

How precise are your timestamps?

Every record carries the matching engine timestamp and a receive timestamp taken in hardware on the network adapter, synchronized against a GPS clock source over PTP: nanosecond resolution, sub-microsecond accuracy to UTC.

Do GPU results match the CPU?

Yes. On the same inputs, the GPU engine and the CPU reference engine produce the same sequence of events. The GPU engine runs the full replay on the card, including queues, orders, accounting and settlement.

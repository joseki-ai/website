Products · Simulation & Backtesting

Market simulation and backtesting

An event-driven simulator for order-book, intraday and long-horizon strategies, with configurable fill, latency and transaction cost models, stress scenarios and GPU-parallel parameter sweeps.

Request early access →
Modes

Simulation modes

The same strategy code runs at each level of detail, from full order book replay to daily bars.

order book

Order book replay

Full-depth replay for market making and high-frequency strategies, with queue position, latency, cancels and partial fills.

event-driven

Event-driven

Trades and quotes processed in sequence for intraday strategies, with fills against recorded quotes after latency.

bars

Bar-based

Daily to monthly bars for portfolio strategies, with rebalancing, transaction costs, financing and borrow.

multi-asset

Multi-asset

Many instruments and venues under shared capital, margin and risk limits.

Market model

Fill, latency and cost models

Fill, latency and transaction cost assumptions are explicit parameters, set per venue and per run. Defaults are conservative.

fills

Fill models

FIFO and pro-rata matching per venue, queue position estimation from price-level data, probabilistic and partial fills.

latency

Latency models

Feed, order entry and order acknowledgement latencies, fixed or sampled from measured distributions.

costs

Transaction costs

Fee schedules and tiers, maker rebates, temporary and permanent market impact, slippage for bar backtests, financing and borrow.

orders

Order types, time in force and instructions

Limit, market, stop and stop-limit orders; day, GTC, GTD, IOC and FOK time in force; post-only, reduce-only and iceberg instructions.

venue rules

Venue rules

Tick and lot sizes, minimum quantities, rate limits, auctions and settlement.

capital

Capital and risk

Margin, position and exposure limits shared across strategies.

Stress

Stress scenarios and validation

Replayed markets can be modified to test a strategy under adverse conditions. Results are evaluated with out-of-sample and resampling methods.

  • latency spikes
  • reduced liquidity
  • wider spreads
  • price gaps
  • fee changes
  • venue outages
  • historical stress windows
  • walk-forward analysis
  • out-of-sample periods
  • block bootstrap
  • parameter sensitivity
  • multiple-testing adjustment
Scale

GPU-parallel parameter sweeps

Parameter sweeps, scenario sets and multi-market runs execute in parallel on GPUs. A CPU reference engine certifies that the GPU engine produces the same sequence of events.

  • Deterministic. Identical data, configuration and build produce identical results.
  • Traceable. Each run records the dataset versions, configuration and build it used.
Accounting

Fill-level accounting and analytics

Results are produced as a fill-level ledger rather than an equity curve alone.

  • positions
  • fees and rebates
  • financing and borrow
  • settlement
  • realized and unrealized P&L
  • exposure
  • turnover
  • drawdown
  • attribution

Products · Workflow

Strategy pipelines as typed, versioned graphs

Data, preparation, features, signals, strategy logic and evaluation are connected as blocks on one canvas. A graph runs as a backtest, a parameter sweep or a scenario set, and is kept under version control.

Request early access →
Blocks

Built-in blocks

Built-in blocks cover each stage of a strategy pipeline. Each block is configurable and versioned.

data

Sources

Market, reference and alternative data at pinned dataset versions.

prepare

Preparation

Cleaning, clock alignment and resampling to time, tick, volume or dollar bars.

features

Features

Library features, option analytics, user-defined and learned features.

signals

Signals

Predictive models, rules and regime filters, with training and validation.

strategy

Strategy

Portfolio construction, position sizing, risk limits and execution logic.

evaluate

Evaluation

Simulator, ledger and analytics.

Connections

Typed connections

Ports carry data types and timing. Incompatible connections are rejected before a run, and no block receives data before its arrival time.

  • typed ports
  • point-in-time inputs
  • validation before run
  • versioned blocks
Custom

Custom blocks

Blocks written in Python or Rust with the SDK use the same interfaces as built-in blocks.

  • custom features
  • custom models
  • custom fill and cost models
  • custom analytics
Runs

Runs and versioning

A graph runs as a single backtest, a parameter sweep, a walk-forward analysis or a scenario set. Graphs are stored as text and versioned, so changes can be reviewed, diffed and rolled back, and every run is reproducible from its graph and dataset versions.

  • backtest
  • parameter sweep
  • walk-forward analysis
  • scenario set
  • diff
  • review
  • roll back
  • reproducible runs
